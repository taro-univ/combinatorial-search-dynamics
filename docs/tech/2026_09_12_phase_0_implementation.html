2. uvによる依存管理

pyproject.tomlのPython範囲を>=3.11,<3.12とし、.python-versionの3.11と一致させた。実行時依存はPhase 0で実際に使用するHydraとTyper、開発用extraはpytestとRuffである。

MLflow、Optuna、DuckDB、PyArrow、Zarr、OR-Toolsは、それぞれ後続Phaseの責務なので依存から外した。生成したuv.lockは直接依存と推移依存を固定する。ローカルのbootstrapとCIは、同じ同期コマンドを使用する。

uv sync --all-extras --locked

scripts/bootstrap.shはuvがなければ導入し、その後は上記コマンドだけで環境を再構築する。.env作成、pipによる二重管理、Codex CLIの自動導入は行わない。

3. Hydra設定の最小構成

configs/config.yamlは値を集約するファイルではなく、次の設定グループを合成する入口として実装した。

研究条件は分類別YAMLに置く。未実装の機能はimplemented: falseで明示されるため、設定が存在することと実行機能が存在することを混同しない。seed、token上限、評価時のtest利用原則、保存先などもPythonコードではなくYAML側に置いた。

設定API

src/llm_search_dynamics/config.pyは三つの役割を持つ。

  1. compose_config()がHydraのdefault compositionを実行する。
  2. resolved_config()が補間解決後の設定を通常のPython辞書として返す。
  3. validate_repository()が必要ファイル、Python指定、設定合成、必須グループを検証する。

設定ディレクトリまたはroot YAMLが存在しない場合は、対象pathを含むFileNotFoundErrorで失敗する。Hydraの構文・合成エラーもrepository validationの診断結果へ変換する。

4. CLIの責務

lsd doctor

実行中のPythonが3.11か、uvがPATH上にあるか、Phase 0のファイルとHydra設定が正しいかを検査する。.envや環境変数を読み取らず、API key、LLMサーバー、GPU、DVC remoteを成功条件に含めない。

lsd validate-repository

Phase 0で実在すべき構成と、解決済みHydra設定の全必須グループを検証する。実験データのschema検証とは責務を分けた。

lsd validate-data

既存コマンドとの互換性のために残したaliasである。Phase 0ではデータ検証が未実装であることを表示してから、repository validationを実行する。実データ検証はPhase 1でこの名前本来の責務として実装する。

Codex CLI

lsd codexとscripts/run_codex.shは開発補助用であり、研究対象LLMのadapterではない。bootstrapやCIから切り離し、研究環境の成立条件に含めていない。

5. テストとCPU CI

unit testでは、パッケージversion、repository root、.env形式の空行・コメント・引用符、秘密値の非表示、Hydra composition、必須設定グループ、設定欠落時の明確な失敗、repository validationを検査する。

integration testはCLIからvalidate-repositoryを呼び出す。mock LLMすら必要とせず、ネットワーク、GPU、大容量データ、DVC remoteなしで完了する。

.github/workflows/ci.ymlはUbuntu上でPython 3.11とuvをセットアップし、次の順序で実行する。

uv sync --all-extras --locked
uv run ruff check .
uv run ruff format --check .
uv run pytest tests/unit tests/integration

7. 秘密情報の扱い

Hydra YAMLにはcredential用の値や環境変数展開を置いていない。.env.exampleにも秘密値を含めず、Phase 0では秘密情報が不要であることだけを記載した。

.envは.gitignoreの対象であり、今回の作業では内容を表示・変更・Git追加していない。doctorも.envを読まないため、診断出力へ秘密値が混入しない。この性質は環境変数へテスト用secretを設定し、出力に現れないことをunit testで確認している。
